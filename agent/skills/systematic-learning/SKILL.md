# Systematic learning

## Principle

Hang an isolated idea on a tree: origin, place, contrast, limits. Not a flat definition.

## Voice

Follow `prose-style`.

## Output

See `skill://html-card`.

## Structure (this order)

### 1. Essence

Explain it to a non-specialist:

- What is it? (one sentence)
- What pain exists without it?
- Why now? (technical preconditions, timing)

### 2. Map

- **Above** — the frame it sits in
- **Below** — parts and schools
- **Beside** — easy mix-ups: `A vs B — one-line split`

### 3. History

- Timeline
- People and what they added
- Live debates

### 4. Cases

One or two:

- A classic case and a counter-intuitive one
- For each: setting, how it is used, why it was chosen

### 5. Limits

- When it works / fails / hurts
- Beginner mistakes

## Workflow

### Step 1 — search in parallel

1. The idea — mechanism, plain explanation, beginner guides
2. Placement — contrasts, history, originators
3. Edge — limits, mistakes, field cases

### Step 2 — cross-check

- Several sources → trust
- One source → mark `[single source]`
- Conflict → show both sides and citations

### Step 3 — HTML card

Five sections. Cite the load-bearing facts. Keep it short.

## Checklist

- [ ] A non-specialist can follow it
- [ ] Above / below / beside are all present
- [ ] Timeline
- [ ] Concrete cases
- [ ] Failure modes

## Anti-patterns

- Dictionary opening ("X is a technology that…")
- No contrasts
- Only upsides
- Single source
- Conclusions without cases
